# Sculptural Generators verification

Verified **29 October 2026, Pacific/Auckland**, in the `shaboomi/terraForge` fork, based on commit `e662aa2`. No upstream repository, installed user profile or physical plotter was modified. The pre-existing local Comic Ink and Spiral Sawtooth packages were preserved and are outside this change.

## Delivery and visual inspection

Three self-contained `.tf-plugin.js` files are in `docs/examples/`, with Generators category, no selected input and mandatory Preview → Apply. The border update gives Flowing Ribbons 26 controls, Wave Volume 29 and Organic Contours 23, below the 32-control limit. Four actual SVG/PNG presets, full settings JSON, reusable `.tforge` layouts and an additional 5 mm border SVG/PNG example are in `docs/images/sculptural-generators/`. The updated distribution folder and ZIP are named `Sculptural-Generators-1.0.0-border-update` under `release/sculptural-generators/`; the earlier bundle is preserved.

The SVG previews were visually inspected against all four supplied reference photographs. Woven Curtains has three separated tall ribbons and coherent crossweave. Braided Ribbons has overlapping strips, large openings and dense crossing folds. Wave Volume has related wavy grids with long straight connecting strands. Organic Contours has nested closed curves, a small opening, broad bulges and concentrated pinched folds. The organic proportions and braid settings were refined after the first vector renders.

## Geometry and contract checks

All **34 generator tests** in `tests/unit/sculpturalGenerators.test.ts` passed, covering:

- Valid bounded manifests, required preview, integer seed default 42, Variation strength and the actual output contract.
- Full declared frame, empty margins, finite points, no duplicate whole paths and Standard path/point limits.
- Exact equal-seed repetition; different seeds change geometry; colours preserve it; Variation 0 removes seed influence.
- Density resamples fixed forms; tolerance preserves anchors while refining sampling.
- Cancellation before/during work, monotonic progress and calculation deadlines.
- Useful path/point limit errors with no partial result; Standard rejects an oversized 700-contour run and Extended returns all 700.
- Configured pen IDs resolved from the actual supplied palette, unavailable position rejection, ribbon palette order and distinct family assignments.
- Long vertical volume strands across six azimuths, positive upper/lower gaps under extreme relief, visibility settings and exact elliptical-hole splitting.
- Default organic contours at seeds 42 and 43: closed, positive/increasing area, sampled self-intersection checks and adjacent-contour containment.
- Exact frame intersections and disconnected fragments, adaptive smoothness checks and rotated/cropped compositions with independent borders.
- Removal of identical same-ink strokes, including reversed paths and cyclic/reversed closed contours, while retaining crossings and separate real-pen assignments.
- Exact rectangular border gaps of 0, 3 and 7 mm around final visible bounds for all three generators, after artwork rotation/clipping; original artwork paths, frame dimensions and actual primary pen IDs are preserved.
- Out-of-frame border requests fail with useful available-gap guidance and no partial result. Border vertices count towards the point budget, an empty scene cannot return a border alone, and the original margin placement remains supported.
- Saved pre-update parameter sets validate with defaults for the two new border controls, keeping the current plugin IDs/version compatible with earlier layouts.

An additional **43 existing regression tests** passed across six plugin validation, capacity, processing, Properties UI and atomic transaction files. No application runtime source was modified.

The hollow-volume test was corrected to use a row through the exact footprint centre. App testing exposed that API-1 `pen` dropdowns are all mandatory; optional assignments were adapted to numeric palette positions instead of modifying that API. The guide documents this limitation and rechecking positions after palette changes.

## Real Windows application checks

The four main Electron workflow tests passed in both development and a freshly built **packaged Windows x64 directory app**, Electron 40.6.0 / app 1.0.0. Each run checked its actual profile path and packaged identity before acting, used a disposable profile under `.cache`, and cleaned up only its own directory.

Every generator passed discovery, integer seed controls, cancellation with no applied result, preview isolation from saved layouts/export, minimise/expand, close/reopen, atomic Apply, real configured-pen assignment, unchanged palette ordering and active pen, Undo/Redo of the complete composition, in-place update with stable IDs/placement, and update Undo/Redo restoring geometry/settings. Save → app restart → reopen → Edit with restored the controls and regenerated identical path geometry. Multi-pen ribbons and volumes remained one undoable composition across their separate pen items.

The border update reran all six packaged-app tests. Each of the three main workflows now applies a 3 mm artwork-relative border, updates its gap to 7 mm alongside a seed change, verifies undo/redo of the complete composition, then saves/reopens and verifies that the enabled border and 7 mm gap restore and regenerate identically. The four border-free presets are refreshed through the same packaged-app authoring pass, and the extra bordered vector preview was visually inspected.

The fourth test passed for the braid preset, crossweave fully off, stale-preview invalidation after changing seed and correct saved unfilled stroke paths. A separate packaged-app authoring pass produced all four delivered `.tforge` presets and verified their parameters, colours and display stroke.

A fifth packaged-app test passed for **combined and per-group G-code export**. All three configured volume family colours survive optimized combined output; joining stays off, and the pen-down count equals the source path count. Split export creates three group files, each containing only its group's colour. Combined export retains the fork's existing global travel optimization and colour metadata. These plugins impose no new pass order or pen-change commands; use per-group files for manual multi-pen plotting. Actual pen IDs remain saved in the document's group assignments. Ordinary unordered G-code does not acquire the ordered-plugin `pen=` extension.

Reproduction:

```powershell
node scripts/build-sculptural-generators.mjs
node scripts/preview-sculptural-generators.mjs
npx vitest run tests/unit/sculpturalGenerators.test.ts
npm run typecheck
npm run build
npx playwright test --config=tests/e2e/playwright.config.ts tests/e2e/sculptural-generators.spec.ts
```

Set `TERRAFORGE_SCULPTURAL_EXECUTABLE` to an absolute executable path to test the packaged app. Set `TERRAFORGE_WRITE_SCULPTURAL_PRESETS=1` and select the `author four` test only when deliberately regenerating delivered layouts; normal test runs skip authoring. A runner that blocks Electron needs desktop process access, while the tests still use isolated profiles and never connect to hardware.

During pull-request preparation, the full unit/component suite was also attempted: 2,286 tests passed, including all 34 generator tests. The restricted runner blocked an existing registry junction test; rerunning its file with normal filesystem access passed all 15 tests. The unchanged `tests/unit/rendererPluginConversion.test.ts` still failed to load with `SyntaxError: Invalid or unexpected token`, including when rerun separately with normal filesystem access. That existing Windows test-loader failure remains disclosed for review; no renderer-conversion files were modified.

No physical plot was run. Extreme deformations with dense/coarse polylines can require finer tolerance or Extended capacity, as documented in the control guide.
